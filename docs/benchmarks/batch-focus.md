P1 core is a **materialized external-subtransform** (host-API

core *composability*, not a device-resident core embedded in a
single kernel.

### Diagnostic reading (review §3 rules)

- first high, steady normal → JIT/compile or first cache fill;
- steady tracks analytical GM bytes → materialization / transpose / boundary writeback;
- core time dominates → sub-transform length, thread layout, or external-core call granularity;
- p95 / max spike → sync, allocator, thermal, or runtime scheduling (re-measure in independent processes before interpreting);
- env hash mismatch → do not interpret performance; recalibrate first.

A1P1 beats the in-table A0P0 path by a wide margin at every
shape (the vendor sub-block core is much faster than our
triton local stage in the A1 flow). Against the vendor
*whole* transform the picture is shape-dependent — see the
guard tables above. This historical artifact is unchanged: Issue
#6 PR-E later promoted only the exact `N=2048,B=16,c2c,dit` cell
into the separate `config/composition_table.json`; it still does
not enter the general selector table, and the cost model has no
general A1 family. The finding is shape-bound evidence, not a
global resident-pipeline claim.

## What the evidence does not prove

- single-card, single software stack: the four-cell is a single-process measurement, the canary is multi-process; no multi-card scaling claim, no cross-driver-version claim (the env fingerprint gates reuse to this card *family* and stack)
- guard agreement is measured on the focus rounds; the holdout is used only for selection validation (top-K / recall / regret), never for guard agreement — a different shape family could still disagree
- the vendor baseline is the runtime's `torch.fft` lowering; Kunlunxin does not publish kernel sources, so internal vendor structure stays opaque (see the inventory)

## Frozen selector vs experimental

- frozen: only guard-clearing winners measured in the clean rounds enter `config/selector_table.json`, validated against the shared design space and the live env fingerprint at load time
- experimental: holdout rows, packet canary, bounded-search variants and A1P1 external-core canary — reported above, never promoted on a single round
